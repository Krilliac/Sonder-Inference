## 3. Bounded Exception Message Policy, Intended Behaviour Changes, and Test Boundaries

### Bounded Exception Messages
`FormatBoundedExceptionMessage(stage, ex)` in `src/backends/llamacpp/request_guards.cpp` maps the exception category (`std::bad_alloc`, `std::regex_error`, `std::out_of_range`, `std::length_error`, `std::invalid_argument`, `std::runtime_error`, or unknown) plus a static SI operation stage name into a bounded ASCII string (`<= 256` bytes). It **never** copies `ex.what()` verbatim because llama.cpp exceptions such as `llama_grammar_accept_token` (`src/llama-grammar.cpp:1599`) and `llama_grammar_parser` (`src/llama-grammar.cpp:122-696`) embed generated pieces or input slices in `what()`. `BuildSampler` also drops the echoed token text from `"preserved token does not map to exactly one token id"`, clears `out` and `grammar_out` on any failure, and rethrows `std::bad_alloc` from grammar init so OOM maps to `ErrorCode::kLoadFailed` (never `kInvalidArgument` or `kDecodeFailed`); `FormatChat` maps `std::bad_alloc` to `ErrorCode::kTokenizeFailed` (never `kInvalidArgument`).

### Intended Behaviour Changes
The following inputs were previously accepted or handled ambiguously and are now explicitly rejected with `ErrorCode::kInvalidArgument`:
- **Stop strings containing an embedded NUL byte** (rejected by `ValidateStopSequences`, hooked in `llamacpp_core_backend.cpp::run_tokens`; empty stops are also rejected and skipped safely in `StopSequenceFilter::Push`).
- **Empty lazy-grammar trigger patterns** (rejected by `ValidateGrammarInputs`).
- **`media_prompt_parts` entries carrying a `media_index` when `media_blobs` is empty** (or when no `mmproj` is loaded; rejected by `ValidateMultimodalRequest`).

By contrast, `top_k` values in `(n_vocab, 128*1024]` (for example `top_k = 50000` on a 32k-vocab model, which `SamplingConfig` permits up to 100,000) remain **accepted** and are clamped via `ClampTopK(p.top_k, n_vocab)` before `llama_sampler_init_top_k`. Only `top_k > 128*1024` (`kMaxBackendProbeCandidates`) is rejected.

### Test Coverage & Verification Boundaries
- **Directly tested without weights (`test_request_guards.cpp`):** all pure validators in `request_guards.hpp/.cpp`, `ClampTopK`, `StopSequenceFilter` empty-string safety, `RunGuarded` (including `oom_code` overrides), and `FormatBoundedExceptionMessage`.
- **Directly tested with the bundled vocab-only GGUF fixture (`ggml-vocab-llama-bpe.gguf`):** `ProbeGrammarMask` / `BuildSampler` (live EOG `GGML_ABORT` prevention, OOB accepted tokens, OOB `logit_bias`, `top_k = n_vocab + 1000` clamping acceptance, `top_k > 128*1024` rejection, invalid lazy regex prompt-free error, and preserved-token prompt-free error).
- **Not tested without weights:** the guards hooked inside `Generate()`, `GenerateSingleLocked()`, and `BatchWorkerLoop()` (which require a non-vocab-only loaded context with weights), as well as the `Try*` exception wrappers (`TryDecode`, `TryEncode`, `TrySetSampler`, `TrySampleToken`, `TryApplySampler`, `TryAcceptSampler`, `TryStateSeq*`).
